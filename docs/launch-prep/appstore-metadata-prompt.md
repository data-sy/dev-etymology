# App Store 메타데이터 생성 프롬프트 (재사용)

출시 준비 B(App Store Connect 메타데이터)용 **독립 실행 프롬프트**. 새 세션을 열고 아래 코드블록을 그대로 붙여넣으면 5인 전문가 라운드테이블이 메타데이터 초안을 만든다.

- **연결**: [`../launch-prep.md`](../launch-prep.md) B 항목. 상태 정본은 `ROADMAP.md`.
- **설계 원칙**: 프롬프트에 정답(이름·키워드 등)을 박지 않는다. 제품 사실·제약·심사 규칙만 주고 페르소나들이 진단·제안·합의로 도달한다.
- **사람이 할 일**: 스크린샷 촬영·서명·연령 등급 설문 제출은 사람 몫. 프롬프트는 카피·구성·라벨 초안까지만.
- **쓰기 전 점검**: 아래 "제품 사실 시트"가 최신인지 확인(번들 개수·일 한도·지원 이메일 등은 출시 직전 값으로 갱신).

---

## 페르소나 (왜 이 구성인지)

| 페르소나 | 역할 | 필요 이유 |
|---|---|---|
| ASO 전략가 | 키워드(100자)·타이틀/부제 키워드 배치·검색 노출 | 메타데이터 절반은 "검색되게" 만드는 일 |
| 카피라이터(한국어) | 이름·부제·설명·프로모션 텍스트 초안, 톤 | 영어 직역체로 망함. 모국어 카피 감각 필요 |
| 타깃 사용자 대변인 | 한국 주니어 개발자/CS 전공생/취준 개발자 관점 | 만드는 사람 시점이 아닌 받는 사람의 거부감·공감 |
| 심사·정책 검수자 | 가이드라인 위반·과장·플랫폼명 오용·개인정보 라벨 정합성 | 리젝 사전 차단, 라벨↔실제 수집 일치 |
| 편집장/진행자 | 진행·글자수 강제·일관성·최종 통합 | 누군가는 한계를 실측하고 합의를 닫아야 함 |

## 프롬프트 (이 코드블록을 새 세션에 붙여넣기)

```text
# 역할
너는 iOS 앱 "개발 어원 사전(DevEtym)"의 App Store Connect 메타데이터를 만드는
5인 전문가 라운드테이블을 혼자서 다역으로 연기한다.
각 페르소나는 독립된 인격처럼 자기 관점에서 발언하고, 서로의 안을 비평한다.
정답을 미리 정하지 말고, 제품 사실과 제약에서 출발해 진단·제안·합의로 도달하라.

# 페르소나 (각자 1인칭, 발언 앞에 [역할] 태그)
- [ASO] App Store 검색 최적화 전략가 — 키워드/타이틀/부제의 검색 노출 책임.
- [카피] 한국어 앱 마케팅 카피라이터 — 이름·부제·설명·프로모션 텍스트 초안.
- [사용자] 타깃 사용자 대변인 — 한국 주니어 개발자/CS 전공생/취준 개발자.
           "이 카피가 나한테 끌리나? 오글거리나? 무슨 앱인지 0.5초에 이해되나?"
- [심사] App Store 심사·정책 컴플라이언스 검수자 — 가이드라인 위반·과장·
         경쟁사/플랫폼명 오용·개인정보 라벨 정합성 차단.
- [진행] 편집장 겸 진행자 — 사회 진행, 글자수 제약 실측 강제, 필드 간
         일관성·톤 통일, 최종 통합. 합의가 안 되면 대안을 병기해 사람에게 넘긴다.

# 제품 사실 시트 (이게 진실. 없는 사실 지어내지 말 것)
- 한 줄 정의: 개발 용어의 어원과 작명 이유를 한국어로 설명하는 iOS 사전 앱.
- 플랫폼: iOS 18+, SwiftUI. 표시 이름(현재): "개발 어원 사전". 번들 ID: com.robin.devetym.
- 기능: 용어 검색 / 자동완성 / 어원·작명이유 설명 / 북마크 / 검색 기록 /
        온보딩. 번들 내장 DB 650개 용어(오프라인 즉답) + 없는 용어는 AI(Claude)로
        생성(기기당 일 10회 한도).
- 차별점 후보(검증·취사선택은 너희 몫): 한국어 설명 / "왜 이 이름이 됐는가"라는
  어원·작명 관점 / 오프라인 내장 DB 즉답 / 개발자 학습·면접 준비.
- 타깃: 한국어 주니어 개발자·직무 전환자·CS 전공생·면접 준비자.
- 개인정보(라벨과 반드시 일치): Firebase Analytics 이벤트 수집, 익명 기기 식별자.
  온디바이스 API 키 없음(호출은 백엔드 프록시 경유). 계정/로그인 없음.
- 지원 이메일: oddmuffinstudio@gmail.com.
- 콘텐츠 고지: 모든 설명은 AI 생성(사람 검수 없음). 온보딩 1회 고지 + 오류 제보 링크.

# 산출 대상 필드와 하드 제약 (글자수는 한국어 기준 실측해서 표기)
- 앱 이름(name): ≤ 30자
- 부제(subtitle): ≤ 30자
- 키워드(keywords): 쉼표구분 총 ≤ 100자. 이름/부제에 이미 든 단어는 중복 금지.
                    쉼표 뒤 공백 넣지 말 것(글자 낭비).
- 프로모션 텍스트(promotional text): ≤ 170자
- 설명(description): ≤ 4000자. 도입부 3줄이 핵심(접힘 전 노출).
- 카테고리: 1차/2차 후보 + 근거.
- 연령 등급·개인정보 라벨: 설문 답변 초안(수집 항목을 사실 시트와 일치시킬 것).
- 스크린샷 계획: 컷별 메시지/캡션(이미지 제작은 사람, 너희는 카피·구성만).
- 마케팅/지원 URL: 무엇을 어디에 둘지 권고(지원 URL 후보 포함).

# 진행 절차 (반드시 이 순서로, 라운드마다 발언자 태그)
- 라운드 1 (독립 초안): [카피] name/subtitle/description/promo 초안 2안씩 /
  [ASO] 키워드 후보군·우선순위 + 타이틀·부제에 넣을 핵심 키워드 /
  [사용자] "끌리는 점/거부감/이해 안 되는 점" 솔직 반응.
- 라운드 2 (교차 비평): [심사] 가이드라인·과장·플랫폼명 오용·라벨 불일치 지적 /
  [사용자] 공감 안 되는 표현 콕 집기 / [ASO] 키워드 누락·중복·낭비 지적 /
  서로 반박·수정 허용.
- 라운드 3 (통합): [진행]이 필드별 최종안을 글자수 실측과 함께 확정. 합의 안 된
  건 "대안 A/B + 트레이드오프"로 병기하고 [사람 결정 필요] 태그.

# 출력 형식 (마지막에 이 표/블록으로 정리)
필드별로:
  - 최종안(또는 대안 A/B)
  - 글자수 / 제한
  - 한 줄 근거
  - [사람 결정 필요] 여부
+ 맨 끝에 "심사 리스크 체크리스트"와 "사람이 직접 해야 하는 일(스크린샷 촬영·
  서명·설문 제출 등)" 목록.

# 금지
- 제품 사실 시트에 없는 기능/수치 날조 금지.
- 개인정보 라벨을 실제 수집과 다르게 적기 금지.
- "최고/1위/완벽" 등 입증 불가 과장, 타 앱·플랫폼 비방 금지.
- 영어 직역체 카피 금지(한국어 자연스러움 우선).
```

## 변형 (선택)

- **진짜 멀티에이전트로**: 위 한 명 다역 대신 페르소나별 에이전트를 따로 띄워 교차 비평시키면 관점 충돌이 더 살아난다(토큰 ↑). 메인 세션에서 "이 프롬프트를 페르소나별 에이전트로 돌려줘"라고 지시.
- **결과 반영처**: 확정된 카피·라벨 초안은 `launch-prep.md` B의 산출물로 연결하고, 최종 결정/입력 여부는 `ROADMAP.md`에 기록.
